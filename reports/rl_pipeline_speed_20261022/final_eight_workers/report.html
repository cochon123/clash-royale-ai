Where the time remains

Median seconds across each configuration's two runs. Encoding is nested inside act_batch; act_batch is nested inside launch. Act includes CPU work, masks, sampling, device transfers and GPU inference, so it is not pure GPU execution. Exposed wait is the wait still visible to the scheduler after overlap. These bars are separate measurements and must not be added together.

Residual/reset/orchestration is approximate: total − launch − exposed wait − consume − publish − PPO. Publish may also occur within an update, so small nested overlap remains. Native reset/step/mask request sums are concurrency diagnostics, not wall-time components; their latency can overlap across workers. First-wave reset also includes native process startup.

Memory boundaries and run health
Every trainer and all its native children ran in an isolated transient user service with MemoryMax=8G, MemorySwapMax=0, OOMPolicy=kill and whole-cgroup cleanup. A supervisor required ≥12GiB host available RAM before each launch, polled every 0.5s and would stop only its current benchmark unit below 6GiB available RAM or on a cgroup memory-cap event. No other jobs were stopped; no caches were cleared.
Cgroup memory in GiB versus elapsed seconds since the full matrix began; colors identify configurations and dashed lines identify seed 2026.
Hard caps are enforced by the kernel between samples. Peak is the maximum of cgroup memory.peak, systemd MemoryPeak and sampled current memory. This eight-worker result is the tested operating point; 16 workers are not recommended as safe from earlier speed alone.
Method, limitations and lessons
All runs use the same native engine binary, pool, parent checkpoint and initial state. Seed 777 order: baseline → g1 → g2. Seed 2026 reverses that order. Policies remain fixed while games within a wave are active; PPO happens between waves. Engines are local simulated games; no network, phone game, installations or long production training were needed.
Encoding, inclusive policy action work, exposed native wait, PPO and reset/orchestration remain useful optimization targets. Use decisions/second alongside games/minute because policy trajectories change game length and the number of decisions. First-wave timings are the cleanest comparison from the initial model, but first-wave native startup/reset is included.
